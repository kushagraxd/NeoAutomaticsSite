2) API Routes (App Router)
Create these server routes with POST only, JSON in/out, Zod validation, IP rate-limit, moderation, and error handling. Never stream key to client.
/app/api/ai/chat/route.ts (Buyer chatbot)
Input: { messages: Array<{role:"user"|"assistant"|"system", content:string}>, context?: { product?: string } }
System prompt (short, deterministic):
You are “Neo AI”, a procurement assistant for Neo Automatics (ISO 9001:2015, PPAP ready; CNC=30; sealed quench + mesh belt; full QA lab). 
Answer concisely for buyers. If details are missing, ask for: annual volume, material grade, tolerance, surface finish, drawing. 
Offer to open the RFQ modal. Never invent capabilities we don't list.
Model: gpt-4o-mini. Temperature 0.3.
Return { reply, suggestions?: string[] }.
/app/api/ai/rfq-helper/route.ts (Spec suggestions/validation)
Input: { product: string, annualVolume?: string, material?: string, finish?: string, notes?: string }
Output JSON:
{ "suggested": { "annualVolume": "range", "material": "grade", "finish": "recommendation", "leadTimeWeeks": 4 }, "checklist": ["PPAP level?", "Drawing?","Tolerance?","Surface roughness?"], "cautions": ["if any"] }
Model gpt-4o-mini, temp 0.2. Bound by our capabilities.
/app/api/ai/extract/route.ts (PDF → spec summary)
Multipart form: file (PDF ≤ 10MB).
Use pdf-parse → first 12k chars → prompt model:
“Extract likely specs (dimensions mm, material grade, tolerance, finish, qty if present). Respond JSON only.”
Return { summary, fields } where fields can prefill RFQ.
/app/api/ai/search/route.ts (Semantic product search)
Input: { q: string }
Compute embedding of q, compare to cached vectors; return top 5 products with scores.
If cache missing, fall back to MiniSearch keyword search.
/app/api/ai/summary/route.ts (Internal mail helper)
Input: raw RFQ payload → return a 5-bullet summary for sales email header.
All routes:
Use limitOrThrow(ip, routeName).
await moderate(userText); if flagged → return 400.
On error → status 500 with { error: "Something went wrong", id } and log.
